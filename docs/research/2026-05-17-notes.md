## 1. Unitree L2 LiDAR stack

### Official SDK structure

`github.com/unitreerobotics/unilidar_sdk2` ships **both** the C++ SDK and a ROS 2 wrapper in one repo:

- `unitree_lidar_sdk/` — core C++ SDK
- `unitree_lidar_ros2/` — ROS 2 wrapper (this is what we want)
- `unitree_lidar_ros/` — ROS 1 wrapper (skip)
- `docs/`

**Implication for our repo:** v3.x BOM and Phase 1 plans reference `discodyer/unitree_lidar_ros2` as a community fork. We **don't need** that fork — the official Unitree SDK now bundles a ROS 2 wrapper. Update repo references.

Verified env: Ubuntu 20.04 + ROS 2 Foxy is the explicitly tested combo per the repo. Humble on 22.04 ARM64 (our setup) should work but isn't NVIDIA-stamped — expect minor friction.

### L2 default network config

Confirmed from the [Unitree user manual](https://oss-global-cdn.unitree.com/static/Unilidar%202%20User%20Manual.pdf):

- LiDAR IP: **192.168.1.62**
- Gateway: 192.168.1.1
- Mask: 255.255.255.0
- Target server (Jetson) expected at: **192.168.1.2**
- L2 → target UDP port: **6101**
- Target → L2 receive port: **6201**

Matches our `BOM.md` §5 + `README.md` Network Topology entries. No change needed.

### Build procedure (Humble on Jetson)

```bash
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
git clone https://github.com/unitreerobotics/unilidar_sdk2.git

# Build the C++ SDK first
cd unilidar_sdk2/unitree_lidar_sdk
mkdir -p build && cd build
cmake .. && make -j$(nproc)

# Build the ROS 2 wrapper
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select unitree_lidar_ros2

# Source
source ~/ros2_ws/install/setup.bash
echo "source ~/ros2_ws/install/setup.bash" >> ~/.bashrc

# Smoke test (no L2 needed — just check the executables exist)
ros2 pkg executables unitree_lidar_ros2
```

Apt dependencies (in addition to ros-humble-desktop):
```bash
sudo apt install -y libpcl-dev ros-humble-pcl-conversions ros-humble-visualization-msgs
```

## 3. librealsense2 on Jetson Orin Nano (JetPack 6.x)

**Use [`jetsonhacks/jetson-orin-librealsense`](https://github.com/jetsonhacks/jetson-orin-librealsense)** — prebuilt kernel modules for librealsense on Orin + JetPack 6 + kernel 5.15.x-tegra. Sequence:
```bash

git clone https://github.com/jetsonhacks/jetson-orin-librealsense.git
cd jetson-orin-librealsense

# 2. Add Intel apt repo
sudo add-apt-repository "deb https://librealsense.intel.com/Debian/apt-repo $(lsb_release -cs) main" -u

# 3. Install
sudo apt install -y librealsense2-utils librealsense2-dev

# 4. ROS 2 wrapper
sudo apt install -y ros-humble-realsense2-camera

# 5. Sanity
realsense-viewer    # GUI app — plug in D456, expect depth + RGB
ros2 launch realsense2_camera rs_launch.py
```

Note: `-dkms` package is **not** available for ARM64. Build from source (jetsonhacks repo handles this).

Reference: [JetsonHacks "Jetson Orin + RealSense in 5 minutes"](https://jetsonhacks.com/2025/03/20/jetson-orin-realsense-in-5-minutes/) (latest tutorial as of 2025).

## 5. 74HC125 half-duplex driver wiring

Standard topology for driving a Dynamixel-style or Feetech TTL bus from a UART:

```
Teensy TX ────► 74HC125 input gate ────►
                                         ├──► TTL bus signal (single wire to servos)
Teensy RX ◄──── 74HC125 second gate ◄──┘
                  │       │
                  │       │   (when DIR high: TX-enable, RX gate muted)
Teensy DIR (GPIO) ┴───────┴   (when DIR low: RX-enable, TX gate muted)
```

- Pull DIR pin high before transmitting; low after TX buffer empty.
- 74HC125 and 74HC126 both work (differ in OE polarity).
- Avoid MAX485 — that's RS-485 (differential), wrong for our single-ended TTL bus.

Reference schematic: [U Alberta PDF](https://sites.ualberta.ca/~mrd1/UART%20full2%20half%20duplex.pdf).

## 6. INA226 on Teensy 4.1

Use **Rob Tillaart's INA226 library** (`github.com/RobTillaart/INA226`) — most maintained.

Wiring (Teensy 4.1):
- SDA → pin 18
- SCL → pin 19
- VCC → 3.3V
- GND → GND
- IN+ / IN- → across the shunt resistor (in series with the rail being measured)

I2C address default: `0x40`. Configurable via solder pads — set unique addresses for 3 INA226 chips:
- Leg rail INA226 → 0x40
- Hip rail INA226 → 0x41
- Jetson rail INA226 → 0x44

Mandatory calibration call:
```cpp
ina.setMaxCurrentShunt(maxCurrent, shuntOhms);
```

Without this, `getCurrent()` and `getPower()` return junk.

**Shunt selection per rail (per Open Decision considerations):**
- Leg rail: 10A+ shunt (Vishay WSLP series 0.001-0.005 Ω, 3W+)
- Hip rail: 10A+ shunt same range
- Jetson rail: stock 1 mΩ on Adafruit/Sparkfun breakouts is fine (3A max draw)

## 7. LM393 + MOSFET battery low-voltage cutoff design

Topology:

```
Battery + ──┬── voltage divider (R1 + R2) ──► comparator IN+ (LM393)
            │                                  │
            │                                  ├── stable Vref ──► comparator IN-
            │                                  │
            │                                  └── comparator OUT ──► MOSFET gate
            │
            └── load (Pololu buck EN pin OR battery main feed via MOSFET drain-source)
```

Hysteresis essential — prevents oscillation around the threshold. Standard trick: positive feedback from output back to IN+ via a high-value resistor. Matt Millman's tutorial has formulas: [mattmillman.com/a-simple-low-battery-detection-circuit-with-hysteresis](https://www.mattmillman.com/a-simple-low-battery-detection-circuit-with-hysteresis/).

Our two-stage design (per `hardware/pcb-mods/README.md` §6):

| Stage | Trip point | Action |
|-------|-----------|--------|
| 1 | **13.0V pack** (3.25V/cell) | Drives Teensy GPIO → publishes `/battery_low` → Jetson `systemctl poweroff` |
| 2 | **12.4V pack** (3.1V/cell) | Drives MOSFET gate → opens battery main feed (autonomous backstop) |

Both stages can share a single LM393 chip (dual comparator). Two separate dividers set the two thresholds. Adjust resistors per formula.

MOSFET candidate: **IRLB3034PBF** (logic-level, Rds(on) ~1.6 mΩ at Vgs=4.5V, Id=195A continuous, surface mount). Or **AOD4184A** if going lower current.

## 9. Fuse selection — Class T, not ANL (BOM fix)

**ANL fuse interrupt rating: 6,000 A.**
**Class T fuse interrupt rating: 20,000 A.**

LiPo dead-short can produce 10-20 kA peaks for a few hundred ms. ANL may "fail open without interrupting" — the fuse element vaporizes but condenses back, fault current continues. Class T is the gold standard for lithium battery protection per [LithiumPro guide](https://www.lithiumpro.co.uk/the-essential-guide-to-lithium-battery-fuses-sizing-types-and-safety/) and [LiFePO4 forum consensus](https://diysolarforum.com/threads/aic-ratings-for-lifepo4-class-t-mrbf.96739/).

**Our 4S LiPo dead-short worst case** (per docs/power-budget.md walking estimates): 14.8V into ~5 mΩ pack internal resistance = ~3000 A peak. ANL might handle it but with no margin. Class T at 20 kA = 6.7× margin.

### Action items
- Update BOM §3 + README + pcb-mods §1: ANL 30A fuse → **Class T 30A fuse**
- Cost delta: ANL 30A ≈ $5-8, Class T 30A ≈ $12-18. Maybe +$10 total.
- Add to `hardware/pcb-mods/README.md` §1 a note about interrupt rating + LiPo justification

## 10. Bambu Lab Liquid Glue vs Magigoo PA — for PA6-CF

**Bambu Lab Liquid Glue is officially supported for PLA / ABS / PETG / ASA / TPU / PET only.** Not officially recommended for PA / PA-CF / PC / PC-CF per Bambu Lab forum + product page.

**Magigoo PA is the recommended adhesive for PA6-CF on textured PEI**, per the Bambu Lab filament guide for PA6-CF and Matterhackers product page.

### Implication for our build
v3.4 BOM substituted Bambu liquid glue (-$15) for Magigoo PA with a "print-test gate" fallback. Per research, the fallback is likely needed — Bambu's general-purpose glue often doesn't hold PA6-CF first layers, and detaching parts mid-print is common.

**Recommendation:** add Magigoo PA back to BOM as $15 line. The savings was theoretical; actual first-layer success matters more than $15.

### Action items
- BOM §8: revert Bambu liquid glue to Magigoo PA (+$15). OR keep Bambu glue but bench-test FIRST and explicitly flag the bench-test gate.
- `docs/setup-print.md` (future): document PA6-CF print profile + adhesion procedure.

## 11. PA6-CF print profile on Bambu P1S

Per [Bambu Lab wiki PA6-CF guide](https://wiki.bambulab.com/en/general/filament-guide-material-table):

| Parameter | Setting |
|-----------|---------|
| Nozzle temp | **280 °C** |
| Bed temp | Maximum (textured PEI ~70°C nominal but preheat 100+°C for soak) |
| Chamber temp | Enclosed (P1S has door) — let chamber heat-soak 15 min |
| Nozzle size | **0.6 mm hardened steel** (carbon fiber abrades brass) |
| Print speed | ≤ 100 mm/s |
| Drier | 24h pre-print (PA is hygroscopic — wet filament prints brittle) |
| Bed adhesion | Magigoo PA on textured PEI |

P1S preheat-bed-and-wait procedure: bed → max → 15 min wait → start print. Suppresses warping.

## 13. OpenVLA / Pi0 on Jetson Orin Nano 8GB (Phase 4 prep)

**Feasibility: tight but possible at INT4 quantization.**

Constraints:
- 8 GB unified RAM shared with ROS 2 + perception + SLAM
- OpenVLA at INT4: ~1.5-2.5 GB model footprint
- Bandwidth-bound, not compute-bound (Jetson's memory bus is the bottleneck per [Eric Liu's benchmarks](https://ericxliu.me/posts/benchmarking-llms-on-jetson-orin-nano/))

Research paper [arxiv.org/html/2412.01034v1](https://arxiv.org/html/2412.01034v1) demonstrates OpenVLA on Jetson **AGX** Orin (16 GB) using TensorRT for vision encoder + MLC-LLM for LLM backbone. Orin Nano 8GB will be tighter — likely sub-real-time inference (single-digit Hz), may need model compression or alternate VLA.

Alternatives:
- **NanoVLA** — under-review paper at [arxiv.org/pdf/2510.25122](https://arxiv.org/pdf/2510.25122), designed for tighter compute budgets
- **TensorRT cross-compilation** — convert PyTorch on a beefier GPU first, deploy `.engine` to Orin Nano

Decision: keep VLA in Phase 4. Will need to re-eval model choice based on RAM available after Phase 2-3 stack is loaded. Open decision row 12 in README already notes the 8GB constraint.
